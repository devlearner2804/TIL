# Toolnet.Be 배포 매뉴얼 61~65

## 61~65. 커밋, 푸쉬, PR 절차

### 61. 변경 파일 확인

작업 후 변경된 파일을 확인한다.

```bash
git status
```

변경 내용을 자세히 본다.

```bash
git diff
```

특정 파일만 확인한다.

```bash
git diff docker-compose.yml
git diff Dockerfile
```

### 62. 변경 파일 스테이징

전체 변경 파일을 추가한다.

```bash
git add .
```

특정 파일만 추가하려면 다음처럼 한다.

```bash
git add Dockerfile
git add docker-compose.yml
git add .github/workflows/backend-deploy.yml
```

스테이징 상태를 다시 확인한다.

```bash
git status
```

### 63. 커밋 작성

커밋 메시지는 변경 내용을 명확하게 작성한다.

```bash
git commit -m "docs: 백엔드 배포 매뉴얼 추가"
```

예시:

```bash
git commit -m "fix: sqlite db mount 오류 대응"
git commit -m "ci: 백엔드 배포 workflow 추가"
git commit -m "chore: docker compose redis 설정 추가"
```

### 64. 원격 브랜치로 push

처음 push하는 브랜치라면 다음처럼 실행한다.

```bash
git push -u origin feature/backend-deploy-manual
```

이미 원격 브랜치가 연결되어 있다면 다음처럼 실행한다.

```bash
git push
```

### 65. PR 생성

GitHub에서 Pull Request를 만든다.

기준:

```text
base: develop
compare: feature/backend-deploy-manual
```

PR 내용에는 다음을 적는다.

```text
1. 작업 목적
2. 변경 파일
3. 배포 영향도
4. .env 변경 필요 여부
5. Docker 재빌드 필요 여부
6. DB 삭제 필요 여부
7. 확인한 명령어
```
