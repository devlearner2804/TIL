# Toolnet.Be 배포 매뉴얼 86~90

## 86~90. 문제 해결

### 86. 컨테이너가 Restarting일 때

컨테이너가 계속 재시작되면 앱 실행 중 오류가 발생한 것이다.

```bash
sudo docker ps
sudo docker logs toolnet-be-dev
```

자주 보는 원인:

```text
1. DB 파일을 열 수 없음
2. .env 값 누락
3. Redis 연결 실패
4. Python 패키지 누락
5. uvicorn 실행 경로 오류
```

### 87. DB 파일 오류

다음 오류가 보이면 DB 파일 마운트를 확인한다.

```text
sqlite3.OperationalError: unable to open database file
```

복구 명령어:

```bash
sudo docker-compose down
sudo rm -rf Grape.db
touch Grape.db
sudo docker-compose up -d --build
```

### 88. Redis 연결 오류

Redis 연결 오류가 나면 `.env`와 compose 서비스 이름을 확인한다.

```bash
cat .env
cat docker-compose.yml
```

Compose 내부에서 Redis 서비스 이름이 `redis`라면 `.env`도 다음처럼 맞춘다.

```env
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_DB=0
```

### 89. Docker 빌드 실패

Docker 빌드가 실패하면 다음 명령어로 직접 확인한다.

```bash
sudo docker build -t toolnetbe_backend .
```

자주 보는 원인:

```text
1. requirements.txt 없음
2. 패키지 설치 실패
3. Python 버전 불일치
4. Dockerfile COPY 경로 오류
5. 네트워크 문제
```

### 90. CI/CD 실패

CI/CD 실패 시 GitHub Actions 로그를 확인한다.

```text
GitHub Repository
→ Actions
→ 실패한 workflow
→ 실패한 job
→ 실패한 step
```

터미널에서 확인할 수 있으면 다음 명령어를 사용한다.

```bash
gh run list
gh run view
```

CI/CD 실패 원인이 secret 누락이면 팀원에게 secret 이름과 등록 여부를 확인해야 한다.
