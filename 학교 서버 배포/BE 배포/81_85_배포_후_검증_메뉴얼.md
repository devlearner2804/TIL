# Toolnet.Be 배포 매뉴얼 81~85

## 81~85. 배포 후 검증

### 81. 컨테이너 상태 확인

배포 후 컨테이너가 정상 실행 중인지 확인한다.

```bash
sudo docker ps
```

정상 상태:

```text
Up
```

문제 상태:

```text
Restarting
Exited
```

### 82. 로그 확인

backend 로그를 확인한다.

```bash
sudo docker logs toolnet-be-dev
```

최근 로그만 보고 싶으면 다음 명령어를 사용한다.

```bash
sudo docker-compose logs --tail=100 backend
```

실시간 로그 확인:

```bash
sudo docker-compose logs -f backend
```

### 83. API 응답 확인

서버에서 API가 열려 있는지 확인한다.

```bash
curl http://localhost:8000
```

health check API가 있다면 해당 주소로 확인한다.

```bash
curl http://localhost:8000/health
```

실제 health check 경로는 팀원에게 확인한다.

### 84. Redis 연결 확인

Redis 컨테이너가 떠 있는지 확인한다.

```bash
sudo docker ps | grep redis
```

Compose 로그를 확인한다.

```bash
sudo docker-compose logs --tail=100 redis
```

backend에서 Redis 연결 오류가 나는 경우 `.env`의 `REDIS_HOST`와 compose의 redis 서비스 이름이 같은지 확인한다.

### 85. 외부 접속 확인

서버 외부에서 접근 가능한지 확인한다.

```bash
curl http://server-ip:8000
```

접속이 안 되면 다음을 확인한다.

```text
1. 컨테이너가 Up 상태인가
2. ports 설정이 맞는가
3. 서버 방화벽이 열려 있는가
4. 클라우드 보안 그룹이 열려 있는가
5. FastAPI가 0.0.0.0으로 실행 중인가
```
