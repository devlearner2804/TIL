# Toolnet.Be 배포 매뉴얼 91~95

## 91~95. 팀 공유와 문서화

### 91. 배포 전에 팀에 공유할 내용

배포 전에 팀 채널에 다음 내용을 공유한다.

```text
1. 배포 예정 브랜치
2. 배포 예정 시간
3. 변경된 기능
4. Dockerfile 변경 여부
5. docker-compose.yml 변경 여부
6. .env 변경 필요 여부
7. DB 삭제 또는 백업 필요 여부
8. 예상 영향 범위
```

### 92. DB 삭제가 필요한 경우 반드시 공유

DB 삭제는 데이터 손실이 발생할 수 있으므로 반드시 팀에 먼저 공유한다.

공유 예시:

```text
DB 구조 변경 때문에 기존 Grape.db 삭제 후 재생성이 필요합니다.
삭제 전 백업 여부 확인 부탁드립니다.
배포 명령어는 docker-compose down 후 Grape.db 재생성, up -d --build 순서입니다.
```

### 93. `.env` 변경이 필요한 경우 공유

`.env` 변경이 필요하면 실제 값을 문서나 채팅에 그대로 올리지 않는다.

공유 예시:

```text
이번 배포에서 .env 항목 추가가 필요합니다.
추가 키: REDIS_HOST, REDIS_PORT, REDIS_DB
실제 운영 값은 서버 관리자에게 확인 후 서버에 직접 반영해야 합니다.
```

### 94. 배포 후 결과 공유

배포가 끝나면 결과를 공유한다.

공유 예시:

```text
백엔드 배포 완료했습니다.
브랜치: develop
컨테이너 상태: Up
확인 명령어: sudo docker ps, sudo docker-compose logs --tail=100 backend
특이사항: Grape.db 빈 파일 재생성 후 정상 실행 확인
```

### 95. 문제 발생 시 기록할 내용

문제가 발생하면 다음 내용을 기록한다.

```text
1. 발생 시간
2. 실행한 명령어
3. 컨테이너 상태
4. 에러 로그
5. 원인 추정
6. 해결 명령어
7. 재발 방지 방법
```
