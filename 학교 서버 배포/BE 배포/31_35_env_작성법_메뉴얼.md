# Toolnet.Be 배포 매뉴얼 31~35

## 31~35. `.env` 작성법

### 31. `.env` 파일의 역할

`.env` 파일은 코드에 직접 적으면 안 되는 환경 설정 값을 따로 관리하는 파일이다.

예시:

```env
DB_NAME=Grape.db
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_DB=0
```

백엔드 앱은 실행될 때 `.env` 값을 읽어서 DB 경로, Redis 주소, 포트, 시크릿 값 등을 사용한다.

### 32. `.env` 파일 생성

서버 프로젝트 폴더에서 `.env` 파일을 만든다.

```bash
touch .env
```

파일을 편집한다.

```bash
nano .env
```

또는 서버에서 `vim`을 사용한다.

```bash
vim .env
```

### 33. 기본 `.env` 예시

현재 기록 기준으로 필요한 기본 값은 다음과 같다.

```env
DB_NAME=Grape.db

REDIS_HOST=redis
REDIS_PORT=6379
REDIS_DB=0
```

`REDIS_HOST=redis`는 Docker Compose 안에서 Redis 서비스 이름이 `redis`일 때 사용한다.

### 34. `.env` 작성 시 주의사항

`.env` 작성 시 다음 규칙을 지킨다.

```text
1. 등호 앞뒤에 공백을 넣지 않는다.
2. 문자열 값에 불필요한 따옴표를 넣지 않는다.
3. 실제 운영 SECRET 값은 Git에 올리지 않는다.
4. 값 끝에 주석을 붙이지 않는다.
5. 팀원이 준 운영 값과 개발 값을 섞지 않는다.
```

잘못된 예시:

```env
DB_NAME = Grape.db
REDIS_HOST= redis
REDIS_PORT=6379 # redis port
```

올바른 예시:

```env
DB_NAME=Grape.db
REDIS_HOST=redis
REDIS_PORT=6379
```

### 35. `.env` 값 확인 명령어

서버에서 `.env` 내용을 확인한다.

```bash
cat .env
```

특정 값만 확인하려면 다음처럼 확인한다.

```bash
grep DB_NAME .env
grep REDIS_HOST .env
```

단, 실제 운영 서버에서 SECRET, TOKEN, PASSWORD가 들어 있다면 화면 공유나 캡처에 노출하지 않는다.
