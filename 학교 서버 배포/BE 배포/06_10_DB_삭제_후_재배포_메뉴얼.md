# Toolnet.Be 배포 매뉴얼 6~10

## 6~10. DB 삭제 후 재배포 절차

### 6. 기존 컨테이너 중지

DB 파일을 다시 만들기 전에 실행 중인 컨테이너를 내린다.

```bash
sudo docker-compose down
```

### 7. 기존 `Grape.db` 삭제

기존 DB 구조가 변경되어 DB를 새로 만들어야 한다면 `Grape.db`를 삭제한다.

```bash
sudo rm -rf Grape.db
```

`rm -rf` 의미:

```text
-r: 디렉터리인 경우 내부 내용까지 삭제
-f: 확인 없이 강제 삭제
```

주의할 점은 `Grape.db`가 실제 운영 데이터라면 삭제 전에 반드시 백업해야 한다.

### 8. 빈 DB 파일 생성

Docker Compose에서 `./Grape.db:/app/Grape.db`처럼 파일 마운트를 사용하고 있으므로, 호스트에 빈 DB 파일을 먼저 만든다.

```bash
touch Grape.db
```

### 9. DB 파일 형태 확인

생성된 `Grape.db`가 디렉터리가 아니라 파일인지 다시 확인한다.

```bash
ls -l Grape.db
```

정상 예시:

```text
-rw-r--r-- 1 user user 0 Jul  9 12:00 Grape.db
```

### 10. Docker Compose 재실행

이미지를 다시 빌드하고 컨테이너를 백그라운드로 실행한다.

```bash
sudo docker-compose up -d --build
```

정상적으로 빌드되면 다음과 비슷한 메시지가 출력된다.

```text
Successfully built <image_id>
Successfully tagged toolnetbe_backend:latest
```
