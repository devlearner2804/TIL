# Toolnet.Be 배포 매뉴얼 11~15

## 11~15. 실행 상태 확인

### 11. 컨테이너 상태 확인

현재 실행 중인 컨테이너 상태를 확인한다.

```bash
sudo docker ps
```

정상 상태라면 backend 컨테이너가 `Restarting`이 아니라 `Up` 상태여야 한다.

정상 예시:

```text
toolnet-be-dev   Up
```

문제 예시:

```text
toolnet-be-dev   Restarting (3)
```

### 12. backend 컨테이너 로그 확인

backend 컨테이너 로그를 확인한다.

```bash
sudo docker logs toolnet-be-dev
```

또는 Compose 서비스 기준으로 확인한다.

```bash
sudo docker-compose logs --tail=100 backend
```

### 13. SQLite 오류 확인

로그에 다음 오류가 있는지 확인한다.

```text
sqlite3.OperationalError: unable to open database file
```

이 오류가 있다면 FastAPI 앱의 `init_db()` 단계에서 SQLite DB 파일을 열지 못한 것이다.

### 14. DB 마운트 문제 여부 확인

다음 조건을 다시 확인한다.

```text
1. docker-compose.yml에 ./Grape.db:/app/Grape.db 파일 마운트가 있는가
2. 호스트의 Grape.db가 삭제된 상태였는가
3. Docker 실행 후 Grape.db가 디렉터리처럼 생성되었는가
4. .env의 DB_NAME이 Grape.db로 되어 있는가
```

이 조건에 해당한다면 코드 문제가 아니라 DB 파일 마운트 문제일 가능성이 높다.

### 15. 정상 실행 여부 최종 확인

다시 컨테이너 상태와 로그를 확인한다.

```bash
sudo docker ps
sudo docker-compose logs --tail=100 backend
```

backend 컨테이너가 `Up` 상태이고 SQLite 오류가 더 이상 발생하지 않으면 정상이다.
