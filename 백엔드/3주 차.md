#  Spring Boot 웹 애플리케이션 계층 구조 (개념 정리)

Spring Boot 기반 웹 애플리케이션은 역할을 나누어 개발하는 “계층형 구조”를 사용한다.  
이 구조는 각 객체가 하나의 책임만 가지도록 만들어 유지보수성과 확장성을 높이는 것이 목적이다.

전체 구조는 일반적으로 다음과 같은 흐름으로 동작한다.

클라이언트 → Controller → Service → Repository → DB  
그리고 데이터 전달 과정에서 Entity와 DTO가 사용된다.

---

#  1. 웹 애플리케이션 계층 구조 개념

웹 애플리케이션은 하나의 기능이 한 곳에서 처리되지 않고 여러 계층으로 나뉘어 처리된다.

이렇게 나누는 이유는 다음과 같다.

- 코드의 역할을 명확하게 분리하기 위해
- 유지보수를 쉽게 하기 위해
- 여러 개발자가 동시에 작업할 수 있게 하기 위해
- 기능 변경 시 영향 범위를 최소화하기 위해

즉, “한 클래스가 모든 일을 하지 않게 만드는 구조”라고 이해하면 된다.

---

#  2. Controller (컨트롤러)

Controller는 웹 애플리케이션에서 가장 앞단에 위치하는 계층이다.  
클라이언트(브라우저, 앱 등)로부터 들어오는 HTTP 요청을 받는 역할을 한다.

Controller의 핵심 역할은 “요청을 받아서 Service로 전달하고, 결과를 다시 클라이언트에게 반환하는 것”이다.

중요한 점은 Controller는 비즈니스 로직을 직접 처리하지 않는다는 것이다.  
즉, 계산이나 데이터 처리 같은 실제 기능은 Service에게 맡긴다.

Controller는 단순히 “입구 역할”만 수행하는 계층이다.

---

#  3. Service (서비스)

Service는 애플리케이션의 핵심 로직이 위치하는 계층이다.  
실제로 기능이 동작하는 대부분의 코드가 Service에 존재한다.

Service의 역할은 다음과 같다.

- 비즈니스 로직 처리
- 데이터 가공
- 여러 Repository 호출을 조합
- 규칙 검증 (예: 작성자 확인, 데이터 유효성 검사 등)

예를 들어 게시판에서 “글 작성”, “수정”, “삭제”, “조회 조건 처리” 같은 실제 기능은 Service에서 처리된다.

Controller가 “요청을 전달하는 역할”이라면, Service는 “실제로 일을 처리하는 역할”이다.

---

#  4. Repository (레포지토리)

Repository는 데이터베이스와 직접 연결되는 계층이다.  
즉, DB에서 데이터를 가져오거나 저장하는 역할만 담당한다.

이 계층에서는 SQL을 직접 작성하기도 하지만, Spring에서는 주로 JPA를 사용하여 메서드 형태로 데이터 접근을 처리한다.

Repository의 특징은 다음과 같다.

- DB 조회 (SELECT)
- DB 저장 (INSERT)
- DB 수정 (UPDATE)
- DB 삭제 (DELETE)

중요한 점은 Repository는 비즈니스 로직을 포함하지 않는다는 것이다.  
오직 데이터 접근만 담당한다.

---

#  5. Entity (엔티티)

Entity는 데이터베이스 테이블과 직접 연결되는 객체이다.  
즉, DB 구조를 자바 객체로 표현한 것이다.

예를 들어 게시판이라면 “게시글 테이블”이 존재하고,  
그 테이블의 구조를 그대로 Java 객체로 만든 것이 Entity이다.

Entity의 특징은 다음과 같다.

- DB 테이블과 1:1로 매핑됨
- 실제 데이터가 저장되는 구조
- 모든 컬럼 정보를 포함할 수 있음
- JPA에서 관리되는 객체

즉, Entity는 “데이터 자체”라고 이해하면 된다.

---

#  6. DTO (Data Transfer Object)

DTO는 데이터를 전달하기 위한 객체이다.  
주로 Controller와 Service 사이 또는 서버와 클라이언트 사이에서 데이터를 전달할 때 사용된다.

DTO의 핵심 목적은 “필요한 데이터만 선택해서 전달하는 것”이다.

예를 들어 Entity에는 비밀번호, 내부 정보 등 민감한 데이터가 있을 수 있는데  
이 데이터를 그대로 클라이언트에게 보내면 위험하다.

그래서 DTO를 사용해서 필요한 데이터만 골라서 전달한다.

DTO의 특징은 다음과 같다.

- 데이터 전달 전용 객체
- 필요한 데이터만 포함
- 보안 및 구조 분리를 위해 사용
- DB와 직접 연결되지 않음

#  8. 전체 구조 정리

Spring Boot 구조는 다음과 같은 흐름으로 이해하면 된다.

1. 클라이언트가 요청을 보낸다
2. Controller가 요청을 받는다
3. Controller는 Service로 요청을 전달한다
4. Service가 실제 비즈니스 로직을 처리한다
5. Service는 Repository를 통해 DB에 접근한다
6. Repository는 DB에서 데이터를 가져온다
7. Entity를 통해 데이터가 객체로 표현된다
8. 필요한 경우 DTO로 변환하여 응답한다
9. Controller가 최종적으로 클라이언트에게 응답한다
