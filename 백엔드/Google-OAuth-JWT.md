# Google OAuth와 JWT 인증

## 1. OAuth란?

OAuth는 사용자의 비밀번호를 직접 전달하지 않고, Google이나 Kakao 같은 외부 서비스를 통해 사용자를 인증하고 필요한 정보에 접근할 수 있도록 하는 방식이다.

이번 과제에서는 Google OAuth 2.0을 사용하여 로그인 기능을 구현했다.

Google 로그인을 사용하면 사용자가 직접 회원가입 정보를 입력하지 않아도 Google 계정을 이용해 로그인할 수 있다.

## 2. OAuth 동작 방식

이번에 구현한 Google OAuth 로그인은 다음과 같은 순서로 동작한다.

1. 사용자가 Google 로그인을 요청한다.
2. 서버가 사용자를 Google 로그인 페이지로 이동시킨다.
3. 사용자가 Google 계정으로 로그인한다.
4. Google에서 사용자 인증을 진행한다.
5. 인증에 성공하면 설정한 Redirect URI를 통해 다시 서버로 돌아온다.
6. Spring Security가 인증된 사용자의 정보를 받아온다.
7. 서버에서 사용자 이메일을 확인하고 JWT를 생성한다.

직접 구현하면서 Redirect URI가 Google Cloud에 등록된 주소와 일치해야 정상적으로 인증된다는 것을 알게 되었다.

## 3. 쿠키 / 세션 / 토큰 인증

### 쿠키

쿠키는 브라우저에 데이터를 저장하는 방식이다.

서버가 브라우저에 쿠키를 전달하면 브라우저가 이를 저장하고 이후 요청에 쿠키를 함께 보낼 수 있다.

쿠키 자체가 인증 방식이라기보다는 세션 ID나 토큰 등의 정보를 브라우저에 저장하고 전달하는 데 사용될 수 있다.

### 세션

세션 방식은 로그인한 사용자의 정보를 서버에 저장하는 방식이다.

로그인에 성공하면 서버에서 세션을 생성하고 클라이언트에게 세션 ID를 전달한다. 이후 클라이언트가 세션 ID를 보내면 서버에서 해당 세션을 찾아 사용자를 확인한다.

서버가 로그인 상태를 관리하기 때문에 관리하기 편하지만 사용자가 많아질수록 서버에서 관리해야 하는 세션도 많아진다.

### 토큰

토큰 방식은 로그인에 성공했을 때 서버가 토큰을 발급하고, 클라이언트가 이후 요청에 토큰을 함께 보내는 방식이다.

서버는 전달받은 토큰이 유효한지 확인하여 사용자를 인증할 수 있다.

이번 과제에서는 JWT를 사용해 Access Token과 Refresh Token을 생성했다.
