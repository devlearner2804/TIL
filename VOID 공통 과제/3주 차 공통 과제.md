# 프로젝트가 진행되는 방법 / 순서
- 프로젝트 아이디어를 정하고 필요한 기능을 정리한다.
- 기능명세서를 작성하여 어떤 기능이 필요한지 문서로 정리한다.
- API 명세서를 작성하여 프론트엔드와 백엔드의 데이터 요청 방식을 정리한다.
- 역할을 분담하고 개발 환경 및 프로젝트 구조를 설정한다.
- 기능별로 개발을 진행하고 중간마다 테스트를 수행한다.
- QA를 통해 오류나 불편한 점을 수정한다.
- 최종 점검 후 릴리즈(배포)를 진행한다.
- 프로젝트 완료 후 회고 및 개선점을 정리한다.

## 개념 정리

### 기능명세서
---
프로젝트에서 필요한 기능들을 문서로 정리한 것이다.
어떤 기능이 필요한지, 어떻게 동작하는지 등을 미리 정리하여 개발 방향을 명확하게 만든다.

### API 명세서
---
프론트엔드와 백엔드가 데이터를 주고받는 방법을 정리한 문서이다.
요청 주소(URL), 요청 방식(GET, POST 등), 응답 데이터 형식 등을 작성한다.

### QA
---
QA(Quality Assurance)는 프로젝트의 품질을 확인하는 과정이다.
기능이 정상적으로 동작하는지 테스트하고 오류나 불편한 점을 찾아 수정한다.

### 릴리즈
---
개발이 완료된 프로젝트를 실제 사용자들이 사용할 수 있도록 배포하는 과정이다.
최종 테스트 후 서버나 웹사이트에 업로드하여 서비스한다.
